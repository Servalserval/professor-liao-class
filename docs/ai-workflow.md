# 這個專案怎麼跟 AI 一起做出來的

整個專案從提問到推上 GitHub，是在一次和 AI 助手（Claude）的對話裡完成的。
這份文件記錄過程，重點放在 **AI 做了什麼、犯了哪些錯、錯誤是怎麼被抓到的**。

## 流程：四個提問

| # | 提問（原文） | AI 做了什麼 |
|---|---|---|
| 1 | 你幫我研究一下現在在虛擬貨幣市場還有哪些現存的套利機會 | 約 20 次網路搜尋，先建立「基準線」（資金費率、基差、美債利率），再列出仍有摩擦的類型，附來源 |
| 2 | 你參考一下推特或是一些網路文章看看其他人有做過什麼有趣的東西嗎 | 收集實際案例與學術論文，同時標出炒作和詐騙 |
| 3 | 你看起來有哪一個是有希望可以繼續往下做的嗎？ | 給出排序和理由，並列出上實盤前要先回答的四個問題 |
| 4 | 你一路往下做，推到 GitHub | 確認資料格式 → 先寫定價核心和測試 → 再寫資料抓取 → 跑真實資料 → 寫文件 |

研究內容整理在 [research.md](research.md)。

## 寫程式的順序

1. **先確認資料長什麼樣子。** 讀 Deribit API 文件確認欄位，抓 Polymarket 的實際題目和結算規則
   （例如「10/31 中午美東時間 Binance BTC/USDT 1 分鐘 K 線的收盤價」）。題目格式猜錯，後面全錯。
2. **先寫數學、先寫測試。** 定價公式用 Monte Carlo 和解析式交叉驗證，曲面用「機率必須單調」這類數學性質檢查。
3. **再寫 I/O。** API client、題目解析、命令列。網路的部分用假資料（mock）測試，不用真的連線也能測。
4. **用真實資料跑一次，然後懷疑結果。**

## AI 犯的錯，以及怎麼被抓到

這一段是課堂上最值得討論的。AI 寫程式很快，但會犯錯；重點是要有機制把錯抓出來。

| 錯誤 | 怎麼發現 | 修正 |
|---|---|---|
| 測試的假資料本身違反無套利（後面到期日的總變異數比前面小） | 測試失敗，檢查後發現是**測試資料**錯，不是程式錯 | 改測試資料；另外把「遇到不合理資料要能處理」變成新功能和新測試 |
| 為了只用價外期權，把一整側的履約價都丟掉，10/31 那條微笑曲線失去了下檔的 skew | 印出每個到期日的節點檢查 | 優先用價外，但只有價內時也保留 |
| 逐點內插加平坦外插，讓「收盤高於 K 的機率」在某些地方隨 K **上升**（機率密度為負） | 畫圖時看到曲線有小波浪，再寫程式檢查單調性 | 改用 SVI 參數化擬合，並加上單調性測試 |
| 過濾「交易所填充值」的規則太粗，把整組平坦的測試資料都刪光 | 既有的測試全部失敗 | 規則改成「同一個值出現 3 次以上，而且不是整條曲線都一樣」 |
| 圖的 x 軸刻度把 72,500 顯示成「72K」 | 打開輸出的圖片看 | 刻度改成直接用履約價 |
| 觸價機率的邊界條件寫成一個永遠只在 B = S 時成立的怪條件 | 自己重讀程式碼時發現 | 改寫成清楚的分支 |
| 反推波動率時假設「機率對 σ 單調」，但價外數位期權不是 | 設計測試時推導發現 | 只在單調的區間內求解 |

最重要的一個不是 bug，而是**判讀**：

> 第一次跑真實資料，到處都是 10¢ 以上的「錯價」，最高 17¢。
> 但所有市場都往同一個方向偏——這通常代表資料有問題，而不是發現了金礦。
> 於是加上「中心價格對齊」：先找出 Polymarket 隱含的中心價格（比期權高約 715 美元），
> 對齊後再比較，剩下的差異才是比較可信的「分布形狀」差異。

**第一個結果很漂亮的時候，最該懷疑。**

## 環境限制與資料來源

- 這次的執行環境連不到 Deribit 和 Polymarket 的 API（網路有白名單），所以課堂快照是用網頁擷取工具抓下來、
  再轉錄成 CSV。這種資料可能有轉錄錯誤、兩邊時間也沒有同步，所以只當教材，`meta.json` 裡寫得很清楚。
- 程式本身是寫成直接呼叫 API 的；在自己的電腦上跑 `python -m pmopt scan --live` 就是真資料。

## 哪些判斷還是要人來做

- **問題值不值得做**：AI 可以列出選項和理由，但要不要投入時間、能承受多少風險，是人的決定。
- **什麼是「真相」**：這裡把期權市場當基準，這是一個假設，不是事實。
- **資料從哪來、可不可信**：AI 會照著資料算，但不一定會主動懷疑資料。
- **結果代表什麼**：edge 是模型下的期望值，不是保證的利潤；要不要交易、合不合法、平台能不能用，都要自己判斷。

## 給想自己試的同學

- 讓 AI **先查資料格式和規則**，不要讓它憑印象寫 parser。
- 要求 AI **先寫測試**，而且測試要檢查數學性質（單調、加總為 1、和 Monte Carlo 一致），不只是「跑得動」。
- 每次拿到結果，**畫出來看**。很多錯誤是在圖上一眼看出來的。
- 結果太好的時候，請 AI 列出「可能讓這個結果是假的」的原因，逐一排除。

## 第二輪：「你就沿著這個一路往下研究」

第二輪是另一個對話。AI 看不到第一輪的對話紀錄（claude.ai 的聊天和雲端開發環境是分開的），
只拿到這個 GitHub repo。所以第一步是**把 repo 當成交接文件**：讀 README、docs、程式碼，跑測試、重現示範結果。
這也說明了為什麼第一輪要把過程寫進 docs：下一個接手的人（或 AI）只看得到 repo。

### 流程

| 步驟 | 做了什麼 |
|---|---|
| 接手 | clone、讀文件與程式、跑 45 個測試、重現離線示範 |
| 找資料 | 試著連 Deribit、Polymarket、Binance，全部被環境的網路政策擋下；網頁擷取工具也一樣 |
| 重看資料 | 發現對齊中心後，觸價盤和期權幾乎一致，偏差只在每日到期盤 → 改問「Polymarket 自己一致嗎？」 |
| 查證 | 網路搜尋：有沒有人做過這個比較（沒有）、兩種題型的結算規則、手續費（各來源說法不一） |
| 寫程式 | `consistency.py`（無模型關係 + 缺口機率）、`history.py`（歷史校準回測）、CLI `check` / `backtest` |
| 測試 | 缺口機率對 Monte Carlo；回測用模擬 API 回應跑完整流程，再用「故意高估尾部」的合成資料確認分析抓得到 |
| 懷疑結果 | 近似套利看起來很乾淨 → 分別反推兩組市場的中心價格 → 差 0.96%，很可能是時間差 |

### 這一輪 AI 犯的錯

| 錯誤 | 怎麼發現 | 修正 |
|---|---|---|
| 推導「觸價 ↑ vs 到期」的無模型條件時，不等式方向寫反（寫成 K ≤ B，應該是 K ≥ B） | 寫程式前，把「收盤在哪一段、哪一腳付錢」逐段列出來 | 改正條件，並寫成測試 |
| 心算缺口機率約 1.2%，程式算出 0.3% | 用 Monte Carlo 驗證，程式是對的；心算漏了「中午之後到月底那 12 小時也可能碰到」 | 保留程式；這個例子寫進文件 |
| Monte Carlo 測試的容差設成 0.002，但要驗證的數字只有 0.003 | 重看測試時發現：公式錯 60% 也會通過 | 改成相對 1% 或 0.0004，並加上缺口很寬的情境 |
| pandas 的 `itertuples` 會把底線開頭的欄位改名，第一次執行就出錯 | 執行時的錯誤訊息 | 改用 `to_dict("records")` |
| 圖上「成本 $0.960（比 $1 少）」變成亂碼：matplotlib 把兩個 `$` 之間當成數學式 | 打開圖片看 | 跳脫 `$` |
| 標籤疊在線上、標題和副標題重疊 | 打開圖片看 | 調整位置；可靠度圖改成等比例座標 |
| README 寫「最高不超過 1.2%」，實際最大值是 1.23%；寫「任何一個中心價格」，其實只算了三個 | 寫完重讀，逐句對照數字 | 改成精確的說法 |

最重要的仍然是**判讀**：

> 「觸及 ↓77,500 + 高於 78,000 只要 $0.96，兩腳都歸零的機率只有 0.3%」——
> 這比第一輪的結果更像真的：不用假設期權是對的，結算來源也相同。
> 但再多問一句「兩組市場以為 BTC 在哪裡？」，答案是相差 0.96%。
> 用同一個中心價格算，組合就不便宜了。

**換了一個更乾淨的方法，還是要再懷疑一次。**

### 環境限制

- 網路：這個雲端環境只允許套件庫等少數網域，連不到資料來源，所以沒有新資料，
  `backtest` 也只能用模擬回應測試。要在雲端環境跑，需要在環境設定的網路存取裡加入
  `www.deribit.com`、`gamma-api.polymarket.com`、`clob.polymarket.com`、`api.binance.com`（或 `data-api.binance.vision`）。
  在自己的電腦上跑則沒有這個問題。
- 權限：AI 想直接 `pip install -r requirements.txt`（剛從網路 clone 的 repo），被自動權限檢查擋下；
  改成指名安裝 PyPI 上的 scipy、matplotlib、pytest。這是合理的安全機制：安裝陌生 repo 指定的套件，本來就該多看一眼。

### 這一輪還是要人來決定的事

- **要不要開網路權限、在哪裡跑 `collect`**：同步資料是分辨「真錯價」和「時間差」的唯一辦法。
- **回測的期間與門檻**：要看幾個月？價格多舊就不算？這些選擇會影響結論，應該在看結果之前先決定。
- **就算同步資料裡近似套利還在**，結算爭議、資金鎖到月底、平台資格，都要自己評估。
