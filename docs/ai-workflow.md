# 這個專案怎麼跟 AI 一起做出來的

整個專案從提問到推上 GitHub，是在一次和 AI 助手（Claude）的對話裡完成的。
這份文件記錄過程，重點放在 **AI 做了什麼、犯了哪些錯、錯誤是怎麼被抓到的**。

## 流程：四個提問

| # | 提問（原文） | AI 做了什麼 |
|---|---|---|
| 1 | 你幫我研究一下現在在虛擬貨幣市場還有哪些現存的套利機會 | 約 20 次網路搜尋，先建立「基準線」（資金費率、基差、美債利率），再列出仍有摩擦的類型，附來源 |
| 2 | 你參考一下推特或是一些網路文章看看其他人有做過什麼有趣的東西嗎 | 收集實際案例與學術論文，同時標出炒作和詐騙 |
| 3 | 你看起來有哪一個是有希望可以繼續往下做的嗎？ | 給出排序和理由，並列出上實盤前要先回答的四個問題 |
| 4 | 你一路往下做，推到 GitHub | 確認資料格式 → 先寫定價核心和測試 → 再寫資料抓取 → 跑真實資料 → 寫文件 |

研究內容整理在 [research.md](research.md)。

## 寫程式的順序

1. **先確認資料長什麼樣子。** 讀 Deribit API 文件確認欄位，抓 Polymarket 的實際題目和結算規則
   （例如「10/31 中午美東時間 Binance BTC/USDT 1 分鐘 K 線的收盤價」）。題目格式猜錯，後面全錯。
2. **先寫數學、先寫測試。** 定價公式用 Monte Carlo 和解析式交叉驗證，曲面用「機率必須單調」這類數學性質檢查。
3. **再寫 I/O。** API client、題目解析、命令列。網路的部分用假資料（mock）測試，不用真的連線也能測。
4. **用真實資料跑一次，然後懷疑結果。**

## AI 犯的錯，以及怎麼被抓到

這一段是課堂上最值得討論的。AI 寫程式很快，但會犯錯；重點是要有機制把錯抓出來。

| 錯誤 | 怎麼發現 | 修正 |
|---|---|---|
| 測試的假資料本身違反無套利（後面到期日的總變異數比前面小） | 測試失敗，檢查後發現是**測試資料**錯，不是程式錯 | 改測試資料；另外把「遇到不合理資料要能處理」變成新功能和新測試 |
| 為了只用價外期權，把一整側的履約價都丟掉，10/31 那條微笑曲線失去了下檔的 skew | 印出每個到期日的節點檢查 | 優先用價外，但只有價內時也保留 |
| 逐點內插加平坦外插，讓「收盤高於 K 的機率」在某些地方隨 K **上升**（機率密度為負） | 畫圖時看到曲線有小波浪，再寫程式檢查單調性 | 改用 SVI 參數化擬合，並加上單調性測試 |
| 過濾「交易所填充值」的規則太粗，把整組平坦的測試資料都刪光 | 既有的測試全部失敗 | 規則改成「同一個值出現 3 次以上，而且不是整條曲線都一樣」 |
| 圖的 x 軸刻度把 72,500 顯示成「72K」 | 打開輸出的圖片看 | 刻度改成直接用履約價 |
| 觸價機率的邊界條件寫成一個永遠只在 B = S 時成立的怪條件 | 自己重讀程式碼時發現 | 改寫成清楚的分支 |
| 反推波動率時假設「機率對 σ 單調」，但價外數位期權不是 | 設計測試時推導發現 | 只在單調的區間內求解 |

最重要的一個不是 bug，而是**判讀**：

> 第一次跑真實資料，到處都是 10¢ 以上的「錯價」，最高 17¢。
> 但所有市場都往同一個方向偏——這通常代表資料有問題，而不是發現了金礦。
> 於是加上「中心價格對齊」：先找出 Polymarket 隱含的中心價格（比期權高約 715 美元），
> 對齊後再比較，剩下的差異才是比較可信的「分布形狀」差異。

**第一個結果很漂亮的時候，最該懷疑。**

## 環境限制與資料來源

- 這次的執行環境連不到 Deribit 和 Polymarket 的 API（網路有白名單），所以課堂快照是用網頁擷取工具抓下來、
  再轉錄成 CSV。這種資料可能有轉錄錯誤、兩邊時間也沒有同步，所以只當教材，`meta.json` 裡寫得很清楚。
- 程式本身是寫成直接呼叫 API 的；在自己的電腦上跑 `python -m pmopt scan --live` 就是真資料。

## 哪些判斷還是要人來做

- **問題值不值得做**：AI 可以列出選項和理由，但要不要投入時間、能承受多少風險，是人的決定。
- **什麼是「真相」**：這裡把期權市場當基準，這是一個假設，不是事實。
- **資料從哪來、可不可信**：AI 會照著資料算，但不一定會主動懷疑資料。
- **結果代表什麼**：edge 是模型下的期望值，不是保證的利潤；要不要交易、合不合法、平台能不能用，都要自己判斷。

## 給想自己試的同學

- 讓 AI **先查資料格式和規則**，不要讓它憑印象寫 parser。
- 要求 AI **先寫測試**，而且測試要檢查數學性質（單調、加總為 1、和 Monte Carlo 一致），不只是「跑得動」。
- 每次拿到結果，**畫出來看**。很多錯誤是在圖上一眼看出來的。
- 結果太好的時候，請 AI 列出「可能讓這個結果是假的」的原因，逐一排除。
